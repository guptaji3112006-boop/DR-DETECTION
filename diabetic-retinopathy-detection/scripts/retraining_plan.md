# DR Classifier Retraining Plan (APTOS Dataset)

This document provides a controlled, 4-phase retraining plan for Member 2 (Training Engineer) to isolate and measure the impact of class weighting and preprocessing fixes on the model's specificity. 

**Objective:** Achieve a target specificity >= 85% while maintaining sensitivity >= 90%.

---

## Prerequisites
- **Environment:** Kaggle Notebook (or equivalent with `DR_TRAIN_IMAGES_DIR` pointing to `/kaggle/input/aptos2019-blindness-detection/train_images`).
- **Splits:** Use the exact deterministic `train_split.csv` and `validation_split.csv` splits generated by the initial run to prevent data leakage.
- **Seeds:** Record all NumPy and TensorFlow seeds. Keep them constant across experiments.
- **Architecture:** EfficientNetB3 backbone (weights='imagenet') + GlobalAveragePooling2D + Dropout(0.3) + Dense(5).

---

## Experiment Phases

> **Important:** Change only *one variable* at a time between experiments.

### Phase A: Reproducible Baseline
Validate that the previous run can be accurately reproduced before introducing fixes.
- **Loss:** Scalar Focal Loss (`alpha=0.25`, `gamma=2.0`).
- **Class Weights:** Unused (None).
- **Preprocessing:** Include `/ 255.0` scaling.
- **Augmentations:** Unclipped.
- **Goal:** Replicate the original behavior (extremely high sensitivity, very low specificity).

### Phase B: Preprocessing Fixes
EfficientNetB3 inherently includes a rescaling layer (`Rescaling(1./255)`). Passing `img / 255.0` double-scales the inputs, degrading image dynamics.
- **Loss:** Scalar Focal Loss (same as Phase A).
- **Class Weights:** Unused (None).
- **Preprocessing:** Remove `/ 255.0` (inputs must be `[0, 255]`).
- **Augmentations:** Apply `tf.clip_by_value(img, 0.0, 255.0)` *after* augmentations.
- **Goal:** Measure the isolated impact of restoring standard dynamic range.

### Phase C: Class Weighting
The APTOS dataset is severely imbalanced. Grade 0 (majority) weight is `0.405`, while Grade 1 is `1.979`. We must determine if balanced weights help or hurt specificity (downweighting Grade 0 might increase false positives).
- **Loss:** Replace custom focal loss with `SparseCategoricalCrossentropy`.
- **Class Weights:** Pass `class_weight_dict` to `model.fit()`.
- **Preprocessing:** Fixed (`[0, 255]`).
- **Augmentations:** Clipped (`[0, 255]`).
- **Goal:** Measure if penalizing minority classes helps correct the decision boundary.

### Phase D: Alternative Loss (Optional)
If Phase C fails to meet targets, explore alternative loss functions natively compatible with class frequencies (e.g., categorical focal crossentropy or label smoothing).

---

## Handoff & Evaluation Protocol
1. **Checkpoint:** Save the best candidate from the above experiments as a new `.keras` artifact. Record its SHA-256 hash.
2. **Metadata:** Save the exact `training_history.pkl`, `train_split.csv`, and `validation_split.csv` alongside the model.
3. **Threshold Tuning:** Hand the new checkpoint over to the Validation Team (Member 4). They will run `corrected_pipeline.py` to fit the temperature and threshold exclusively on the development partition.
4. **Publishing:** `selected_runs.json` must NOT be updated until the new candidate is explicitly verified on the independent IDRiD Testing set.
